Gesamtfluss der Berechnung

Es gibt 5 verschiedene Eingabewege fur den Warmebedarf: CSV-Upload und CSV+Monate gehen direkt in den Lastgang, wahrend Monatswerte, Jahresverbrauch und Gebaudedaten zuerst die SIGLINDE-Synthese durchlaufen. Der resultierende Stundenlastgang wird dann in einer 6-Phasen-Kaskade auf die Erzeuger verteilt. Darauf aufbauend laufen Wirtschaftlichkeit, Strom-Bilanz, Netzberechnung und Optimierung.
Alle Berechnungen laufen im Browser — kein Server notig. Hover uber die Knoten fur Erklarungen, Klick springt zum Detail.

Hover = Erklarung • Klick = zum Detail springen • Gestrichelt = Feedback-Schleife

Architektur

Das gesamte Tool ist eine Single-Page-Anwendung in einer HTML-Datei (Index.html, ~30.000 Zeilen). Die Berechnungslogik ist in einem CalcEngine-IIFE (Immediately Invoked Function Expression, ab ~Zeile 21878) gekapselt.

CalcEngine (IIFE)

Enthalt alle Kern-Berechnungen als CalcEngine.run(params)-Pipeline:
1. Temperatur laden → 2. Vorlauf berechnen → 3. calcLastgang → 4. calcTWW → 5. calcAnalyse → 6. calcErzeugerProfile → 7. calcDispatch → 8. calcMetriken → 9. Jahresdauerlinie + kalteste Woche

Signaturfunktion sigH()

H(T) = A / (1 + (B / (T - T0))^C) + D + max(mh×T + bh, mw×T + bw) Jedes Profil hat 8 Koeffizienten: {A, B, C, D, mh, bh, mw, bw} • Erster Term: Sigmoid-Funktion (temperaturabh. Heizgrenze) • Zweiter Term: D (Grundlast-Offset) • Dritter Term: Maximum aus zwei Geraden (Heiz- und Warmwasser-Grundlast) Gewichtete Mischung (2 Profile moglich): Bedarf(d) = gew1 × sigH(T_mittel(d), profil1) + gew2 × sigH(T_mittel(d), profil2)

Gewichtung: mix(d) = gew1×sigH(T_m(d), P1) + gew2×sigH(T_m(d), P2) 5. 24h-Schablone: Jeder Tag auf 24h verteilen, normieren 6. Skalierung auf Gesamtenergie (Fall 4/5) oder monatsweise (Fall 3) 7. 5. calcErzeugerProfile() — Stundenprofile

Berechnet fur jeden Erzeuger das stundengenaue Kapazitats- und Stromprofil (8760h).

CalcEngine ⚙Erzeuger-Stundenprofile calcErzeugerProfile()
Nennleistung + Temperatur → stundengenaue Kapazitat & Stromverbrauch

Warmepumpen (typ: 'wp')

Fur jede Stunde t: 1. Quelltemperatur bestimmen: Luft-WP: T_q(t) = T_aussen(t) (direkt Aussentemperatur) Geo-WP: T_q(t) = 10 + 2 × sin(2π × (d-30)/365) Stabile ~10°C, saisonaler Swing ±2°C Hinweis: Im Dispatch (_deckungen8760) wird (d-75) verwendet — Abweichung zum CalcEngine-Modell (d-30)! Fluss-WP: T_q(t) = max(0.5, 10 + 8 × sin(2π × (d-119)/365)) Grosse Schwankung 2-18°C, Minimum 0.5°C Frostschutz-Abschaltung bei T_q < 2°C 2. COP berechnen (via calcCOP): hub = max(T_VL(t) - T_q(t), 0.1) (min. 0.1 K Temperaturhub) COP(t) = (273.15 + T_VL(t)) / hub × Gutegrad COP_ref = (273.15 + 35) / (35 - 2) × Gutegrad (Referenz: A2/W35, d.h. 2°C Quelle, 35°C Vorlauf) COP-Begrenzung: max. 8 im Dispatch, NICHT in CalcEngine 3. Leistungs-Derating: P_waerme(t) = P_nenn × COP(t) / COP_ref P_strom(t) = P_waerme(t) / COP(t) Gutegrade (Standard): Luft-WP: 0.42 Geo-WP: 0.50 Fluss-WP: 0.56 Ergebnis: e.profile = { waerme: Float32Array(8760), // verfugbare Warmeleistung [kW] strom: Float32Array(8760), // elektr. Bedarf [kW] cop: Float32Array(8760), // stundlicher COP tq: Float32Array(8760) // Quelltemperatur }

Nicht-WP-Erzeuger (Kessel, BHKW, etc.)

P_waerme(t) = P_nenn = konstant (keine Temperaturabhangigkeit) P_strom(t) = 0 (kein Strombedarf fur Kessel) BHKW: Stromproduktion = P_th × σ (Stromkennzahl, Standard: 0.45) σ = P_el / P_th (Verhaltnis elektr. zu therm. Leistung)

10. calcJahresscheiben() — NPV / Barwert

Projektion aller Kosten uber die Laufzeit mit Energiepreiseskalation und Diskontierung.

Wirtschaft 📈Jahresscheiben / Cashflow calcJahresscheiben()
Bausteine + Energiekosten → NPV-Barwert uber T Jahre

Datensammlung

Sammelt alle aktiven Bausteine (Technologie + Infrastruktur + Aufschlage). Fur jede Komponente:

  • Investitionskosten [€]
  • Jahrliche Betriebskosten = Inst% + Wart% des Invest + Arbeit [€/a]
  • Nutzungsdauer n → Reinvestitionszeitpunkte

Jahresscheibenberechnung

Fur jedes Jahr y = 0..T (Betrachtungszeitraum): Invest(y) = Anfangsinvest (y=0) + Reinvestitionen (y=n, 2n, ...) Betrieb(y) = jahrliche Betriebskosten (konstant nominal) Energie(y) = Energiekosten(0) × (1 + Eskalation)^y Gesamt(y) = Invest(y) + Betrieb(y) + Energie(y) Diskontfaktor(y) = 1 / (1 + r)^y NPV(y) = Gesamt(y) × Diskontfaktor(y) Barwert = ∑ NPV(y) fur y = 0..T

Synchronisation

Diskontsatz r = Kapitalzins (aus VDI 2067). Damit sind Annuitatenmethode und NPV-Methode konsistent — beide Methoden liefern identische Rankings.

WGK aus NPV

WGK_NPV = Barwert / (Nutzwarme_MWh × T) / 10 [ct/kWh]

11. Warmegestehungskosten (WGK)

Zentrale Kennzahl: Was kostet eine kWh Warme aus dem Gesamtsystem?

Wirtschaft 💲WGK in ct/kWh
Kapital + Betrieb + Energie − Gutschriften / Nutzwarme

Formel

WGK = (Kapital-JK + Betriebs-JK + Energiekosten - BHKW-Stromerlos) / Nutzwarme_MWh / 10 Einheit: ct/kWh (Division /10 konvertiert Euro/MWh → ct/kWh)

Bestandteile

  • Kapital-JK: Summe aller Baustein-Annuitaten (VDI 2067)
  • Betriebs-JK: Instandhaltung + Wartung + Bedienung
  • Energiekosten: Brennstoff × Preis / Wirkungsgrad pro Erzeuger
  • BHKW-Gutschrift: Stromerlos (Eigenverbrauch + Einspeisung) wird abgezogen
  • Nutzwarme: Gesamte abgegebene Warme aller Erzeuger [MWh/a]

12. Warmenetz — Hydraulische Netzberechnung

Berechnet Rohrdimensionierung, Druckverluste, Pumpenauslegung und Warmeverluste fur das gezeichnete Warmenetz.

Warme 🌡Netzhydraulik & Warmeverluste calcWaermenetz()
Topologie + Lastprofile → DN-Rohre, Druckverlust, Pumpenstrom, Netzverluste

Lastakkumulation

Fur jede Leitung im Netz: Von den Endverbrauchern zur Zentrale werden die Warmelasten aufaddiert. Massenstrom pro Leitung: m_dot [kg/s] = Q_kW / (c_p × ΔT) mit c_p = 4.18 kJ/(kg·K), ΔT = Vorlauf - Rucklauf

DN-Dimensionierung (Darcy-Weisbach)

Fur jede Leitung wird der Rohrdurchmesser so gewahlt, dass die Fliessgeschwindigkeit v ≤ v_max (typisch 1.0-1.5 m/s): v = m_dot / (ρ × A) mit A = π/4 × d² Druckverlust (Darcy-Weisbach): Δp = λ × (L / d) × (ρ / 2) × v² Reynolds-Zahl: Re = v × d / ν Rohrreibung: λ nach Swamee-Jain (Naherung fur Colebrook-White) Einzelwiderstande: Zuschlag (Zeta-Werte oder pauschaler Faktor)

Kritischer Pfad & Pumpe

Der langste Druckverlust-Pfad (Zentrale → entferntester Abnehmer) bestimmt die erforderliche Pumpen-Forderhohe: H_pump [m] = Δp_krit / (ρ × g) Pumpenstrom: P_pump [kW] = m_dot × g × H_pump / (η_pump × 1000)

Warmeverluste

Q_verlust [kW/m] = U × (T_VL - T_boden) mit U = Warmedurchgangskoeffizient [W/(m·K)] Jahresverluste = ∑ Q_verlust(t) fur t = 1..8760 Verlustanteil = Q_verlust_a / Q_gesamt_a × 100%

Bestandsnetz-Logik

Bei networkLocked = true: DN-Werte werden nicht neu berechnet. Investitionskosten = 0 (oder anteiliger Sanierungsanteil). Rohrdaten kommen aus dem gezeichneten/importierten Netz.

Topologie & BFS

Algorithmus 🌐Downstream-Last per BFS 15c-stromnetz-calc.js · recalcStromnetz()

Pro Leitung wird die downstream-Last ermittelt: alle Verbraucher/Erzeuger „hinter" der Leitung (vom Trafo aus gesehen). BFS traversiert nur zu Knoten mit höherem oder gleichem TYPE_RANK — verhindert den Rückweg durch parallele Einspeisepunkte (z.B. zwei Trafos an einer NSHV).

TYPE_RANK = { NAP:0, Schaltanlage:1, Trafo:2, NSHV:3, UV:4, Verbraucher:5, WP:5, Lade:5, Nsa:5, KWK:5, Wind:6, PV:6, Batterie:6, Reserve:7 } bfsDownstream(leitung, loadFn): src = niedrigerer Rang (versorgungsseitig) sink = höherer Rang visited = {src} queue = [sink] while queue: cur = queue.pop() load += loadFn(cur) (Verbrauch oder Erzeugung) nb in adj[cur] mit RANK[nb] >= RANK[cur]: queue.push(nb) return load

Worst-Case-Strom (Kabelauslegung)

P_load = bfsDownstream(lt, assetVerbrauch) // reine Last [kW] P_gen = bfsDownstream(lt, assetErzeugung) // reine Einspeisung [kW] P_net = P_load - P_gen // Netto (Vorzeichen) P_worst = max(P_load, P_gen) // Worst-Case für Querschnitt I_A = P_worst·1000 / (√3 · U_ref · cos φ) // Strom für Auslegung I_A_sign = P_net·1000 / (√3 · U_ref · cos φ) // vorzeichenbehaftet für ΔU I_max = I_max[qs] · parallelCount (NS oder MS aus 14a-Tabelle) ausl% = I_A / I_max · 100

Spannungsfall (lokal + kumulativ)

// Lokal pro Leitung R_seg = R_kabel[qs] · laenge[m] / 1000 / pc [Ω] ΔU_V = √3 · R_seg · I_A_sign // vorzeichenbehaftet! ΔU_pct = ΔU_V / U_ref · 100 // Kumulativ vom Trafo aus (BFS) nodeVoltDrop[nextId] = nodeVoltDrop[cur] + ΔU_V ΔU_kumPct[lt] = nodeVoltDrop[snkId] / U_N · 100 // Färbung der Leitung if ausl > 100: rot ← bottleneck elif |ΔU_kumPct| > 5: rot ← VDE-Grenze elif |ΔU_kumPct| > 3: gelb elif ausl > 80: gelb else: grün isReverse = (P_net < -0.5): gestrichelt (Rückspeisung)

PV(t) = Globalstrahlung(t) × Ausrichtungsfaktor × Modulwirkungsgrad × kWp → Stundliche Erzeugung [kW] BHKW_el(t) = BHKW_th(t) × σ (Stromkennzahl)

Stundliche Bilanz

Fur jede Stunde t: Erzeugung(t) = PV(t) + BHKW_el(t) Bedarf(t) = WP_el(t) + Stromkessel_el(t) + Quartier(t) 1. Direktverbrauch = min(Erzeugung, Bedarf) 2. Uberschuss = Erzeugung - Direktverbrauch 3. Batterie laden: ladung = min(Uberschuss, P_bat_max, (Kapazitat - SOC) / eta_lade) SOC += ladung × eta_lade 4. Restbedarf = Bedarf - Direktverbrauch entladung = min(Restbedarf, P_bat_max, SOC × eta_entlade) SOC -= entladung / eta_entlade 5. Einspeisung = Uberschuss - ladung 6. Netzbezug = Restbedarf - entladung

Kennzahlen

Eigenverbrauchsquote = Eigenverbrauch / PV_ges × 100% Autarkiegrad = 1 - Netzbezug / Gesamtbedarf × 100% BHKW-Stromerlos: Eigenverbrauch: spart Netzbezugspreis (~35 ct/kWh) Einspeisung: Einspeisevergutung (~8-16 ct/kWh) + KWK-Zuschlag

18. runOptimierung() — Rastersuche

Systematische Suche nach der besten Erzeugerkombination und -dimensionierung. Nutzt Multi-Worker-Parallelisierung fur schnelle Berechnung.

Optimierung 🔍Adaptive Rastersuche (Multi-Worker) _runOptWorker() / _doRunOptimierung()
Betrachtungsjahr wahlen → Grobsuche → Top-Kandidaten → Feinsuche → Top 3

Betrachtungsjahr

Der Nutzer wahlt ein Betrachtungsjahr (2026-2050) im Optimierungs-Panel. Der Lastgang wird VOR der Optimierung auf dieses Jahr skaliert: scaledLastgang = _optGetScaledLastgang(targetYear) → Nutzt denselben Mechanismus wie _rescaleLastgangForYear() → Der aktuelle systemState bleibt unverandert Ergebnis-Anzeige zeigt "Betrachtungsjahr: 20XX" uber den Varianten.

Multi-Worker-Parallelisierung

numWorkers = min(navigator.hardwareConcurrency - 1, 8) → Nutzt alle verfugbaren CPU-Kerne (minus 1 fur UI) Arbeitsteilung: • Grobsuche: Kombinationen werden auf N Worker verteilt • Jeder Worker berechnet seinen Anteil unabhangig • Ergebnisse werden zusammengefuhrt, Top-Kandidaten extrahiert • Feinsuche: Ein Worker optimiert die Top-Kandidaten Fortschrittsanzeige: Prozent + verstrichene Zeit + Anzahl Kerne Fallback: Bei 1 Kern oder Worker-Fehler → Main-Thread (_doRunOptimierung)

Zweistufiger Algorithmus

  1. Grobsuche:
    • Alle Einzel-, Paar- und Tripel-Kombinationen der aktiven Erzeuger
    • Gaskessel, Heizol und alle anderen werden als regulare Kandidaten berucksichtigt
    • Adaptive Rasterdichte: 9 Stufen (bis 4 Techs), 7 Stufen (bis 6), weniger bei mehr
    • Leistung pro Erzeuger: stufen = [0..1] × P_max
    • PV und Batterie: unabhangiges Raster
    • Pro Kombination: voller _optDispatch8760() + _optKennwerte2()
    • Top 5 pro Kombination behalten
  2. Feinsuche:
    • Fur jede Top-Kombination: Leistung ±10% der Spitzenlast, 5-kW-Schritte
    • 2 Runden iterative Verfeinerung
    • Solarthermie-Flache ±20% variieren
    • PV/Batterie finales Raster
    • Ergebnis: Top 3 mit vollstandigen Details

PV + Batterie Optimierung

_optPvBatSim8760(pvKwp, batKwh, demandProfile): Stundenweise Simulation: 1. PV-Erzeugung = Profil × kWp 2. Direktverbrauch → Batterie laden → Einspeisung 3. Batterie entladen → Netzbezug calcPvBatOptimierung(): Grid-Search uber pvKwp × batKwh Kombinationen Bewertet nach: Kosten, Autarkie, EE-Anteil

Rechenaufwand

Evaluationen = C(k,1..3) × N^k × PV_stufen × Bat_stufen Beispiel: 4 Erzeuger, N=9, 4 PV, 4 Bat: = (4+6+4) × 9^2 × 4 × 4 ≈ 18.144 Dispatch-Laufe + Feinsuche: ~500 zusatzliche Laufe pro Top-Kandidat Bei Multi-Worker mit 8 Kernen: Grobsuche ~8x schneller
